# 打卡助手（CheckInApp）

一款 Android 打卡工具：在**指定的时间段**与**指定的地点范围**内打卡，自动记录打卡时的**系统时间**与**地点**（经纬度 + 文字地址），并以**日历**形式呈现历史打卡记录。

## 功能特性

- **打卡规则管理**：可添加多条规则，每条规则包含
  - 规则名称
  - 打卡时间段（支持跨午夜，如 22:00 – 06:00；结束整点不计入，如 08:00 规则到 07:59:59）
  - **生效星期**：每天 / 工作日 / 周末 / 自定义星期几
  - 打卡地点（经纬度 + 允许半径，可一键用当前位置填充）
  - 启用/停用开关、编辑、删除
- **一键打卡**：点击“立即打卡”，自动校验
  - 当前系统时间是否在规则时间段内（且当天是生效星期）
  - 当前定位是否在规则地点半径内
  - 两者均满足才记为“打卡成功”，否则给出明确原因（时间外 / 地点外 / 无定位 / 未配置规则）
- **自动打卡**：开启后由前台服务持续监控定位与时间，无需手动点击
  - 时间 + 地点均满足某规则 → **自动记录成功**（同一规则同一打卡时段内只记录一次成功）；
  - **时间符合但地点不符（或定位失败）→ 也会自动记录一条失败打卡**（标注原因，含时间与地点，同规则 30 分钟内不重复，避免刷屏）；
  - 不在任何规则的时间段内 → 不记录
- **拍照打卡**：可开启“打卡时拍照”，手动打卡前先打开相机拍照取证，照片随记录保存、点击可放大查看
- **一键请假**：失败记录（地点外/时间外等）可直接点 **请假** 一键把备注标为“请假”，返岗后再补标即可
- **请假模式**：日历上点击某天可**提前标记为请假**（或取消）——请假当天不产生任何自动打卡记录（含失败记录），日历显示**蓝色请假标记**，主页显示"今日请假·无需打卡"
- **时间段请假/加班**：日历上可给某天添加**时间段标注**（如 09:00-12:00 请假、18:00-21:00 加班），均支持备注
  - 请假时段内自动打卡同样跳过（不产生失败记录）
  - 加班仅作记录展示，不影响自动打卡
  - 日历当天显示对应标记：请假=蓝、加班=珊瑚橙
- **完整留痕**：每次打卡尝试都会记录系统时间、经纬度、逆地理编码地址与结果状态，可添加备注（如迟到原因）、可删除单条记录
- **记录维护**（设置 → 数据 → 记录维护，低调入口+警示确认）：仅用于修正系统打卡产生的录入错误，可修改打卡**时间**（日期+时刻）与**地点**（经纬度+地址，支持"使用当前位置填充"、坐标变化自动重新逆地理编码）；**若修正后的时间与地点均在规则内，状态自动变为成功**（写入对应规则名）；备注、照片不可修改，修改后统计与日历自动更新
- **日历呈现**：按月展示；**只有当天所有生效规则都成功打卡才标绿**；未完成按原因分色（时间外=红、地点外=深橙、定位失败=橙、完全未打卡=灰），一天多种失败原因会显示多个色点；点击某一天查看当天全部记录（时间、地点、地址、状态）
- **统计报表**：主页展示今日状态、本月出勤天数、按时率、连续打卡天数；日历页显示本月出勤与按时率
- **导出表格**：一键导出**本月**或**全部**记录为 **CSV** 或 **Excel(.xlsx)**（Excel 含“打卡记录”与“汇总统计”两个 Sheet），通过系统分享面板保存或发送
  - **汇总统计 Sheet = 月末考勤报表**：记录总数/成功/失败/按时率/**出勤天数/请假天数/加班次数/加班总时长**/各规则成功统计/**按日出勤明细**（✓出勤 ✗未成功 请假 未打卡 加班）
- **数据备份/恢复**：设置页可将**全部数据**（规则 + 记录 + 请假 + 时间段标注）导出为 JSON 备份，换机/重装后完整恢复
- **今日记录**：主页直接列出今天的所有打卡

## 技术栈

| 模块 | 技术 |
| --- | --- |
| UI | Jetpack Compose + Material 3 + Navigation Compose |
| 数据 | Room（KSP 编译） |
| 定位 | 系统 LocationManager（GPS + 网络定位），Haversine 距离校验 |
| 语言/工具 | Kotlin 2.0、AGP 8.7、Gradle 8.9、minSdk 26 / targetSdk 35 |

## 如何构建运行

1. 用 **Android Studio**（建议 Ladybug 或更新版本）打开本项目根目录 `CheckInApp/`。
2. 若提示缺少 `gradle-wrapper.jar`：在项目根目录执行 `gradle wrapper --gradle-version 8.9`（本机需装有 Gradle），或直接让 Android Studio 自动修复 Wrapper。
3. 等待 Gradle Sync 完成并自动下载依赖，然后点击 ▶ Run 安装到模拟器或真机。

> 首次运行会请求**定位权限**，请允许；若使用模拟器，请通过模拟器
> “Extended Controls → Location”设置一个地点，便于测试地点校验。

## 自动发布（GitHub Actions）

推送 `v*` 标签（如 `v2.0`）会自动触发 CI：构建**正式签名的 release APK** 并生成带附件的 GitHub Release（自动生成版本说明）。流程：

```bash
# 1. 修改 app/build.gradle.kts 的 versionName（如 "2.1"）后提交并推送
git add -A && git commit -m "xxx" && git push
# 2. 打标签并推送 → 自动构建发布
git tag v2.1 && git push origin v2.1
```

- 签名密钥通过仓库 **Secrets** 注入：`ANDROID_KEYSTORE_BASE64` / `ANDROID_KEYSTORE_PASSWORD` / `ANDROID_KEY_ALIAS` / `ANDROID_KEY_PASSWORD`；
- 本地开发不受影响：未设置密钥环境变量时 `assembleRelease` 仍可构建（未签名）；密钥文件与口令保存在 `keystore/`（已 gitignore，切勿提交）。

## 使用方法

1. 底部导航进入 **规则** 页，点击右下角 **+** 添加规则：
   - 填写规则名称；
   - 点击时间框选择开始/结束时间；
   - 填写纬度、经度与允许范围（米），或先回到打卡页“刷新定位”后点击“使用当前位置填充”；
   - 保存。
2. 回到 **打卡** 页：
   - 点击 **立即打卡** 手动打卡，结果卡片会显示成功/失败原因、打卡时间与地点；
   - 打开 **自动打卡** 开关（首次会请求定位/通知权限），此后满足时间段与地点时会自动记录，无需手动操作；关闭开关即停止监控；
   - 打开 **打卡时拍照** 开关后，点“立即打卡”会先调起相机拍照，照片随记录保存。
3. 进入 **日历** 页，切换月份查看打卡分布（绿点=成功，红点=失败），点击日期查看当天明细；点 **导出** 可选择本月/全部 × CSV/Excel 导出。
4. 进入 **设置** 页：备份/恢复全部数据、清空打卡记录；**记录维护**（数据 → 最后一项）可修正录入错误的打卡时间与地点（有警示确认，原则上限修正错误）。

## 权限说明

- `ACCESS_FINE_LOCATION` / `ACCESS_COARSE_LOCATION`：打卡时获取当前位置用于地点校验与记录。
- `FOREGROUND_SERVICE` / `FOREGROUND_SERVICE_LOCATION`：自动打卡前台服务持续监控定位。
- `POST_NOTIFICATIONS`（Android 13+）：显示自动打卡监控通知（不授予也不影响自动打卡本身）。
- `INTERNET`：逆地理编码（坐标转地址）时使用。
- 拍照打卡调用系统相机，无需额外权限。

## 备注

- 打卡记录保存在本地 Room 数据库（`checkin.db`），不上传任何服务器。
- 时间校验以设备系统时间为准（即“打卡时系统时间”），地点校验使用 GPS/网络定位。
- 时间段边界精确到秒且**不含结束整点**：如 `07:50 - 08:00` 表示 07:50:00 至 07:59:59 有效，08:00:00（含）起不在范围内。
- 自动打卡的**成功去重按"同一规则同一时段只记一次"**（失败 30 分钟冷却），在**互斥锁内原子执行**，进入时段瞬间的并发触发（闹钟、轮询、定位回调）不会造成重复记录。
- 删除单条记录会**连带删除其取证照片**；清空全部记录会**清理全部照片文件**（备份 JSON 中的照片路径可能因此失效，恢复后照片不显示属正常现象）。
- **省电设计**：自动打卡仅在打卡时段内启用 GPS 高精度定位（60 秒一次）并做完整校验；非打卡时段只用低频网络定位（5 分钟一次）、GPS 关闭、不访问数据库与网络。**时段切换由边界闹钟驱动**：服务会精确计算下一个规则窗口的开始/结束时刻并用 `AlarmManager` 设置闹钟（Android 12+ 未授予精确闹钟权限时自动降级为非精确 `allowWhileIdle` 闹钟），到点唤醒设备立即切换省电/打卡模式，避免低频轮询在系统休眠时错过切换时机；**进入时段前 90 秒还会提前预热定位**（提前开启 GPS、不打卡不产生记录），到点后即可用新鲜定位立即打卡，显著缩短 GPS 冷启动造成的延迟。一天只开一两个短时段的规则，耗电极低。
- **版本约定**：每次加功能或修 bug，`versionCode` 与 `versionName` 同步递增（`versionName` 每次 +0.1，如 1.5 → 1.6）；设置页"关于"显示"第 N 次修订"（N = versionCode），便于直观看出改过多少次。
