# 打卡助手（CheckInApp）

一款 Android 打卡工具：在**指定的时间段**与**指定的地点范围**内打卡，自动记录打卡时的**系统时间**与**地点**（经纬度 + 文字地址），并以**日历**形式呈现历史打卡记录。

## 功能特性

- **打卡规则管理**：可添加多条规则，每条规则包含
  - 规则名称
  - 打卡时间段（支持跨午夜，如 22:00 – 06:00；结束整点不计入，如 08:00 规则到 07:59:59；开始与结束不允许相同，否则规则永不生效，保存时会提示）
  - **生效方式**：每周固定（每天 / 工作日 / 周末 / 自定义星期几）或**轮转班制**（上 N 天休 M 天循环，如“上四休二”，可设周期起点日期；轮转时与星期无关）
  - **打卡地点（一个规则可多个点位）**：主地点（经纬度 + 允许半径，可一键用当前位置填充）＋任意数量的**附加打卡点**（公司两个门、多栋楼等），落在**任一**地点半径内即视为地点符合
  - **WiFi 兜底**（可选）：给主地点或任一附加地点登记 SSID；定位不可用或不可信时连上该 WiFi 即视为到达（室内 / GPS 漂移场景）。可信定位下 GPS 未命中不会被 WiFi 覆盖，避免把判定权交给可伪造的信号
  - **需要下班卡**（可选）：开启后该规则的时间窗**对半分为上班卡与下班卡两个槽位**，各自只记一次，从而得到"上班时刻 + 下班时刻"并能算出真实在岗时长；关闭时（默认）整个时间窗打一次卡即算完成
  - **考勤应到 / 应离时刻**（可选）：仅用于报表的迟到、早退统计，不影响打卡成功与否
  - 启用/停用开关、编辑、删除
- **一键打卡**：点击“立即打卡”，自动校验
  - 当前系统时间是否在规则时间段内（且当天在生效星期 / 轮转班制的上班日内）
  - 当前定位是否落在该规则的**任一**打卡点（主地点或附加地点）半径内；定位不可用或不可信时，连上已登记的 WiFi 亦视为到达
  - 两者均满足才记为“打卡成功”，否则给出明确原因（时间外 / 地点外 / 无定位 / 未配置规则）
- **自动打卡**：开启后由前台服务持续监控定位与时间，无需手动点击
  - 时间 + 地点均满足某规则 → **自动记录成功**（同一规则同一打卡时段内只记录一次成功）；
  - **时间符合、定位已稳定（新鲜 ≤2 分钟）但地点不符 → 自动记录一条失败打卡**（标注原因，同规则 30 分钟内不重复，避免刷屏）；**定位尚未就绪（GPS 冷启动/无信号/位置过期）时不记录失败**，等定位稳定后自动判定——避免清晨首次判定拿到网络粗定位、把正确地点误判成"地点外"而出现"先失败后成功"的噪音记录；
  - 不在任何规则的时间段内 → 不记录
  - **后台运行保障自检**（设置页首卡）：时段外只靠系统闹钟唤醒，因此「精确闹钟权限 / 电池优化白名单 / 后台定位权限 / 通知权限」任一缺失都会表现为“开关开着却没打卡”却不报错；设置页会逐项检测并提供一键跳转
- **打卡提醒**：设置页可开启「打卡提醒」并选提前量（5 / 10 / 15 / 30 / 60 分钟）
  - **已打卡就不提醒**：闹钟触发时先复核该槽位是否已有成功记录 —— 已经打过卡、当天请假 / 放假、或窗口时刻落在时间段请假内，一律不弹通知
  - 开了「需要下班卡」的规则**额外提醒下班卡**（按窗口结束时刻倒推同样的提前量）；没开的规则整窗只提醒一次，避免误导用户去打一次没有意义的卡
  - **跨午夜班次照常**：22:00-06:00 的上班卡提醒在当天 21:45，下班卡提醒在次日 05:45，与班次的考勤归属口径一致
  - 提醒**只发通知、不产生任何记录**，也不需要定位权限；闹钟在重启 / 时间变更 / 规则增删改后自动重排，**关掉开关会立即取消**已排下的那一条，不会残留一次"幽灵提醒"
- **打卡结果反馈**：自动打卡**成功或失败时单独弹一条通知**（可关），并给出**提示音 + 震动**
  - 常驻通知只写"自动打卡监控中"，用户不会盯着它看 —— 打完卡到底成没成，必须主动告知，否则只能事后翻记录
  - **成功**用系统通知音 + 一记短震；**失败**用系统闹钟音 + 两记短震（失败是需要在窗口内立刻补救的事，不该被当成普通消息划掉）
  - **遵循系统铃声模式**：手机调「静音」时不响也不震、「震动」时只震不响 —— 开会时不会因为打卡提醒响铃；两种模式下结果通知照常送达
  - 手动打卡**不重复弹通知**（结果卡片就在眼前），只给声音/震动，体感与自动打卡一致
- **打卡身份确认**：可要求**手动打卡前先过指纹/人脸**（设置 → 打卡身份确认，默认关闭）
  - 对应钉钉的"人脸打卡"：证明是**本人**打的卡，别人拿到手机也代打不了
  - **一条硬规则：门禁永远不能挡住打卡** —— 未录入指纹、没有硬件、硬件暂不可用等任何"验证做不了"的情况一律**放行**，只在界面上明确告知"本次打卡未经身份确认"
  - 只有用户**主动取消**验证才不打卡；单个指纹不匹配不打断（系统会让其重试），连续失败才由系统终结
  - **自动打卡不受此项约束**：后台无人值守无法做生物识别。这正是导出表保留「数据来源」列的意义 —— 手动打卡与自动打卡一眼可分
- **拍照打卡**：可开启“打卡时拍照”，手动打卡前先打开相机拍照取证，照片随记录保存、点击可放大查看
- **一键请假**：失败记录（地点外/时间外等）可直接点 **请假** 一键把备注标为“请假”，返岗后再补标即可
- **特殊日标记（请假 / 放假）**：日历上可把某天标记为**请假**（玫红）或**公司放假**（靛蓝，如国庆、春节），并支持取消
  - 三色刻意**冷暖对立**：正常=绿、请假=玫红（暖）、放假=靛蓝（冷），且特殊日的点比其他标记**大一号**，日历顶部还有**图例**，扫一眼即可分辨
  - 两种标记语义相同——**当天不需要打卡**：自动打卡**完全静默**（不注册定位、不轮询、不写任何记录，含失败记录），主页显示"今日无需打卡"，服务通知显示"已暂停检测"
  - **按区间批量标记**：日历页「区间标记」可一次把连续多天（如国庆 1–7 号）标为放假或请假，也可一键清除该区间；区间含首尾两天
  - 报表中**请假与放假分开计数**，且两者都**不计入"应打卡"**——公司放假不会被算成"缺卡"而拉低出勤率
- **时间段请假 / 放假 / 加班**：日历上可给某天添加**时间段标注**（如 09:00-12:00 请假、14:00-18:00 放假、18:00-21:00 加班），均支持备注
  - 请假 / 放假期段内自动打卡同样跳过（不产生失败记录），口径与打卡规则一致：**不含结束整点**
  - 加班仅作记录展示，不影响自动打卡
  - 日历当天显示对应标记：放假=靛蓝、请假=玫红、加班=珊瑚橙
- **完整留痕**：每次打卡尝试都会记录系统时间、经纬度、逆地理编码地址、验证方式（GPS / WiFi）与结果状态，可添加备注（如迟到原因）、可删除单条记录
- **时钟异常留痕**：时间校验只能依赖设备系统时间，手动改时间即可绕过。记录会带上 GPS 授时与系统时间的偏差，超过 5 分钟即在记录、主页与导出表中标记为“时间不可信”（仅留痕提示，不阻断打卡）
- **记录维护**（设置 → 数据 → 记录维护，低调入口+警示确认）：仅用于修正系统打卡产生的录入错误，可修改打卡**时间**（日期+时刻）与**地点**（经纬度+地址，支持"使用当前位置填充"、坐标变化自动重新逆地理编码）；**若修正后的时间与地点均在规则内，状态自动变为成功**（写入对应规则名）；备注、照片不可修改，修改后统计与日历自动更新
- **审计留痕**：修正**一定会留痕** —— 记录来源标记为"人工修正"，记下首次修正的时刻并**保留原始打卡时刻**；记录卡片显示"✎ 人工修正过（原打卡 …）"，导出的考勤表有**「数据来源」列**（自动打卡 / 手动打卡 / 含人工修正），汇总统计里也有"其中人工修正 N 条"。一张能看出哪里被改过的表才有证据价值，否则可被随意篡改而无从察觉
- **日历呈现**：按月展示；标记优先级为 **放假（靛蓝）> 请假（玫红）> 加班（珊瑚橙）> 打卡结果**；打卡结果中**只有当天所有应打卡规则都成功才标绿**（按记录与规则的**主键**逐条比对，规则改名/删除或存在同名规则都不会误判），未完成按原因分色（时间外=红、地点外=深橙、定位失败=橙、完全未打卡=灰），一天多种失败原因会显示多个色点；点击某一天查看当天全部记录（时间、地点、地址、状态）
- **统计报表**：主页展示今日状态、本月出勤天数、按时率、连续打卡天数；日历页显示本月出勤与按时率
- **导出表格**：一键导出为 **CSV** 或 **Excel(.xlsx)**，通过系统分享面板保存或发送
  - **范围可选**：本月 / **指定月份**（年份翻页 + 月份网格选择，可导出任意历史月份）/ 全部
  - Excel 含“打卡记录”“汇总统计”“考勤日报”三个 Sheet：**汇总统计 Sheet = 月末考勤报表**（记录总数/成功/失败/按时率/**出勤天数/请假天数/放假日数/加班次数/加班总时长**/各规则成功统计/**按日出勤明细**（✓出勤 ✗未成功 请假 放假 未打卡 加班））——指定月份时明细列出该月每天
  - **考勤日报 Sheet**：一天一行，可直接交给 HR。放假 / 请假当天**应打卡列显示 "—"**，不计缺卡、也不参与迟到早退判定
    - **表壳已排好**：第 1~3 行是表名（如"2026年9月 考勤表"）、人员信息（姓名/工号/部门，在设置页填写一次）与导出时间，**冻结前 4 行**滚动时表头常驻，表头**加粗**、各列设了**合适的列宽**，表格末尾留了**员工/主管签字栏** —— 不必再自己排版
    - 三个 Sheet 都有加粗表头与列宽；「打卡记录」「汇总统计」冻结首行
    - **考勤日以"班次开始的那一天"为准**：跨午夜夜班（22:00-06:00）的凌晨段归到前一天，不会被拆成两天、也不会落到非工作日上
    - **在岗时长按班次分别计算再累加**，班次之间的空档（如午休）不计入：上午班 09:00-12:00 + 下午班 14:00-18:00 记 7 小时，而不是"全天首次→全天末次"的 9 小时
    - **迟到 / 早退按班次判定后累加**，跨午夜班次以窗口起点换算，凌晨打卡不会被误判成"早退数小时"
    - 规则开启了"需要下班卡"或配置了"应离时刻"，却只打了一次卡的班次，备注提示**缺下班卡**
    - 这类班次必须打满**上班卡 + 下班卡**两次才算"正常"，只打一次记为"部分打卡"
- **数据备份/恢复**：设置页可将**全部数据**（规则 + 附加打卡点 + 记录 + 请假/放假标记 + 时间段标注，可选内嵌照片）导出为 JSON 备份，换机/重装后完整恢复
- **今日记录**：主页直接列出今天的所有打卡

## 技术栈

| 模块 | 技术 |
| --- | --- |
| UI | Jetpack Compose + Material 3 + Navigation Compose |
| 数据 | Room（KSP 编译） |
| 定位 | 系统 LocationManager（GPS + 网络定位），Haversine 距离校验 |
| 身份确认 | androidx.biometric（指纹 / 人脸），宿主 Activity 为 FragmentActivity |
| 语言/工具 | Kotlin 2.0、AGP 8.7、Gradle 8.9、minSdk 26 / targetSdk 35 |

## 如何构建运行

1. 用 **Android Studio**（建议 Ladybug 或更新版本）打开本项目根目录 `CheckInApp/`。
2. 若提示缺少 `gradle-wrapper.jar`：在项目根目录执行 `gradle wrapper --gradle-version 8.9`（本机需装有 Gradle），或直接让 Android Studio 自动修复 Wrapper。
3. 等待 Gradle Sync 完成并自动下载依赖，然后点击 ▶ Run 安装到模拟器或真机。

> 首次运行会请求**定位权限**，请允许；若使用模拟器，请通过模拟器
> “Extended Controls → Location”设置一个地点，便于测试地点校验。

## 自动发布（GitHub Actions）

推送 `v*` 标签（如 `v2.0`）会自动触发 CI：构建**正式签名的 release APK** 并生成带附件的 GitHub Release（自动生成版本说明）。流程：

```bash
# 1. 修改 app/build.gradle.kts 的 versionName（如 "2.1"）后提交并推送
git add -A && git commit -m "xxx" && git push
# 2. 打标签并推送 → 自动构建发布
git tag v2.1 && git push origin v2.1
```

- 签名密钥通过仓库 **Secrets** 注入：`ANDROID_KEYSTORE_BASE64` / `ANDROID_KEYSTORE_PASSWORD` / `ANDROID_KEY_ALIAS` / `ANDROID_KEY_PASSWORD`；
- 本地开发不受影响：未设置密钥环境变量时 `assembleRelease` 仍可构建（未签名）；密钥文件与口令保存在 `keystore/`（已 gitignore，切勿提交）。

## 使用方法

1. 底部导航进入 **规则** 页，点击右下角 **+** 添加规则：
   - 填写规则名称；
   - 点击时间框选择开始/结束时间；
   - 填写纬度、经度与允许范围（米），或先回到打卡页“刷新定位”后点击“使用当前位置填充”；
   - 保存。
2. 回到 **打卡** 页：
   - 点击 **立即打卡** 手动打卡，结果卡片会显示成功/失败原因、打卡时间与地点；
   - 打开 **自动打卡** 开关（首次会请求定位/通知权限），此后满足时间段与地点时会自动记录，无需手动操作；关闭开关即停止监控；
   - 打开 **打卡时拍照** 开关后，点“立即打卡”会先调起相机拍照，照片随记录保存。
3. 进入 **日历** 页，切换月份查看打卡分布（绿点=成功，红点=失败），点击日期查看当天明细；点 **导出** 可选择范围（本月/指定月份/全部）× 格式（CSV/Excel）导出，选"指定月份"后可用 ◀ ▶ 切换年份、点选月份。
4. 进入 **设置** 页 → **打卡提醒**：打开开关并选提前量（默认 15 分钟），此后上下班卡前会收到通知；已打卡 / 请假 / 放假日自动不提醒。再往下依次是 **打卡反馈**（结果通知 / 提示音 / 震动）与 **打卡身份确认**（手动打卡前需指纹/人脸）。最后填写**考勤表人员信息**（姓名/工号/部门，导出 Excel 时写进表头）、备份/恢复全部数据、清空打卡记录；**记录维护**（数据 → 最后一项）可修正录入错误的打卡时间与地点（有警示确认，原则上限修正错误）。

## 权限说明

- `ACCESS_FINE_LOCATION` / `ACCESS_COARSE_LOCATION`：打卡时获取当前位置用于地点校验与记录。
- `FOREGROUND_SERVICE` / `FOREGROUND_SERVICE_LOCATION`：自动打卡前台服务持续监控定位。
- `POST_NOTIFICATIONS`（Android 13+）：显示自动打卡监控通知与**打卡提醒**（不授予只是收不到通知，不影响打卡本身）。
- 打卡提醒**不需要任何额外权限**：它只读本地数据库并发通知，不复用定位，因此自动打卡关闭时提醒依然可用。
- `VIBRATE`：打卡结果的震动反馈。
- 生物识别**不需要运行时权限申请**：`USE_BIOMETRIC` 由 `androidx.biometric` 库自带的清单合并进来。
- `INTERNET`：逆地理编码（坐标转地址）时使用。
- 拍照打卡调用系统相机，无需额外权限。

## 项目结构

```
app/src/main/java/com/example/checkin/
├── MainActivity.kt              # 入口 Activity
├── data/                        # Room 数据层
│   ├── CheckInRecord.kt         # 打卡记录实体（含 ruleId / 验证方式 / 时钟偏差）
│   ├── CheckInRule.kt           # 打卡规则实体（含班制、应到应离、主地点 WiFi）
│   ├── CheckInSite.kt           # 附加打卡点实体（一个规则多点位）
│   ├── CheckStatus.kt           # 打卡结果状态
│   ├── LeaveDay.kt              # 特殊日标记实体（按天：请假 / 公司放假）
```

## 备注

- 打卡记录保存在本地 Room 数据库（`checkin.db`），不上传任何服务器。
- 时间校验以设备系统时间为准（即“打卡时系统时间”），地点校验使用 GPS/网络定位。
- 时间段边界精确到秒且**不含结束整点**：如 `07:50 - 08:00` 表示 07:50:00 至 07:59:59 有效，08:00:00（含）起不在范围内。
- 自动打卡的**成功去重按"同一规则同一时段只记一次"**（失败 30 分钟冷却），在**互斥锁内原子执行**，进入时段瞬间的并发触发（闹钟、轮询、定位回调）不会造成重复记录。
- 删除单条记录会**连带删除其取证照片**；清空全部记录会**清理全部照片文件**（备份 JSON 中的照片路径可能因此失效，恢复后照片不显示属正常现象）。
- **打卡身份确认的设计取舍**：门禁的默认动作是"**放行**"而不是"拦截"。
  生物识别是**辅助**安全能力，而打卡是有时效的（错过窗口就是缺卡/迟到），
  因此"未录入指纹""没有硬件""硬件暂不可用"这些**设备侧**问题一律放行并明确告知，
  只有"用户主动点了取消"才不打卡 —— 那是明确的意思表示，必须尊重。
  技术上，`BiometricPrompt` 要求宿主是 `FragmentActivity`，故 `MainActivity` 继承它
  （`FragmentActivity` 本身是 `ComponentActivity` 的子类，Compose 相关用法不受影响）；
  门禁放在 Compose 层而非 ViewModel，因为 ViewModel 不该持有 Activity。
- **打卡反馈的设计取舍**：反馈的"存在感"是分级的 —— 常驻通知（低优先级、静默）负责"我还活着"，
  结果通知（高优先级、横幅）负责"这一次成没成"，声音与震动负责用户根本没看屏幕的情况。
  手动打卡省掉结果通知那一级：结果卡片已经在眼前，再弹一条纯属打扰。
  **系统铃声模式优先级高于应用开关**：静音时不响不震、震动模式只震不响 —— 应用不该在用户明确要求安静的场合出声。
- **打卡提醒的设计取舍**：提醒是**独立于自动打卡**的能力 —— 它只读数据库 + 发通知，不需要定位，
  因此自动打卡关闭时提醒照样工作（很多人的用法就是"手动打卡 + 到点提醒"）。
  提醒时刻由 `ReminderPlanner` 纯函数算出，**只排严格未来的那一次**，不做"补发"：
  该函数会在规则变更、开机、服务刷新时被反复调用，补发会让用户在窗口内反复收到同一条提醒。
  全局只保留一个待触发闹钟（同一 PendingIntent 请求码覆盖），因此不会堆积；
  用**非精确闹钟**兜底：未授予精确闹钟权限时降级为 `setAndAllowWhileIdle`，提醒可能晚几分钟但不会丢。
- **省电设计**：自动打卡**只在打卡时段内工作**——时段内启用 GPS+网络高精度定位（60 秒一次）并做完整校验；**时段外（如下班后到次日上班前）完全静默**：不注册任何定位监听、不做任何轮询检查，仅由 `AlarmManager` 边界闹钟在下一个规则窗口的开始/结束时刻唤醒设备（Android 12+ 未授予精确闹钟权限时自动降级为非精确 `allowWhileIdle` 闹钟），夜间零扫描零唤醒，最大化省电；**进入时段前 90 秒预热闹钟**提前开启 GPS 获取定位（不打卡不产生记录），到点即可用新鲜定位立即打卡，缩短 GPS 冷启动延迟。**规则增删改会主动唤醒服务重排闹钟**，静默期也能及时生效。一天只开一两个短时段的规则，耗电极低。
- **隐私**：已关闭系统自动备份（`allowBackup="false"`）——数据库含完整位置历史（经纬度 + 地址），不允许 adb backup / 云备份整体取出。换机迁移请用设置页的「备份数据」导出 JSON。
- **备份格式**（v2.9 起 `version=4`）：记录带审计字段（来源 / 首次修正时间 / 原始打卡时刻），缺字段的旧备份按"自动打卡、未修正"恢复。v2.5 起 `version=3`：附加打卡点按其所属规则在 `rules` 数组中的**下标**关联（规则名允许重复，不能做唯一键）；内嵌照片按记录在 `records` 中的下标关联（同一秒内两条记录的时间戳会重复）。特殊日标记带 `kind` 字段区分请假/放假。**旧格式备份仍可恢复**：缺 `ruleIndex` 时回退按规则名匹配，缺 `kind` 时按请假处理。
- **下班卡的切分点**：开启"需要下班卡"后，时间窗**对半**切分为上班卡槽与下班卡槽（09:00-18:00 → 13:30 起可打下班卡；22:00-06:00 → 次日 02:00 起）。之所以不是"打完第一次就允许第二次"，是因为自动打卡每 60 秒轮询一次——若不限时间，上班卡打完 1 分钟就会被记成下班卡，在岗时长恒为 1 分钟。
- **班次的生效日**：跨午夜规则（如 22:00-06:00）的生效星期以**窗口开始的那一天**为准——"仅周一"的夜班覆盖周一 22:00 至周二 06:00，周二凌晨仍算这一班；周二 22:00 起则不再生效。
- **版本约定**：每次加功能或修 bug，`versionCode` 与 `versionName` 同步递增（`versionName` 每次 +0.1，如 1.5 → 1.6）；设置页"关于"显示"第 N 次修订"（N = versionCode），便于直观看出改过多少次。
